What it does

An agent that reads pages, not pixels.

BAT serializes a page into a clean, structured report the model can act on reliably, then executes every action with real browser tools — no screenshots, no guessing.

🌳

Reads pages for the model

A serializer injected into every frame at document_start builds the PAGE REPORT: an indented accessibility tree with [ref_N] handles, page text, checkbox state and JSON-LD product data — fenced so the model can parse it reliably.

🖱️

Native browser tools

Click, type, set checkboxes, navigate, scroll, run JS — executed via CDP + the scripting API with page-idle waits and a phantom cursor that shows you exactly what the agent is doing on the page.

📁

Collects data to files

A dedup store feeds TSV/CSV in a workspace folder (on disk or embedded storage), and give_file hands the finished file straight into the chat with a Download button.

⚙️

Background collection runs

A service-worker plan runner walks a plan page-by-page with cached extractors (zero model calls per page), checkpoints after every page, and survives panel close and browser restart.

✅

Keeps itself on track

A working checklist the model maintains (set_checklist) plus a per-run event log — both injected into its context every turn, so it never works from memory.

🧲

Whole job boards via ATS

Greenhouse, Lever, Ashby and Workable public JSON APIs — an entire company board in one HTTP call, no tab and no extractor, merged into the same dedup pipeline as scraped rows.

🎓

Course & quiz mode

Detects SCORM / Storyline / Captivate / Articulate pages, dismisses "Resume" dialogs, answers single- and multi-choice questions, clicks Check, and reads pass/fail feedback.

🧠

Persists your work

Chat history mirrors to chrome.storage.local and collected rows live in IndexedDB — both survive panel close and browser shutdown. One fixed workspace, no surprises.

🔒

Model code is untrusted

Extractor source and run_javascript pass a two-layer safety screen (regex denylist + AST alias tracking); sensitive fields are redacted before upload; a site allowlist gates page-changing tools.

The toolset

~30 native tools, offered to the model.

The model sees these as real function calls. Every one runs in the browser — nothing is simulated.

Architecture

Four contexts, one loop.

The extension is split across the four JavaScript contexts a Manifest V3 extension can inhabit — each with a single responsibility.

src/ ├─ content/ injected into every page │ ├─ accessibility-tree.js PAGE REPORT builder │ │ (every frame · document_start · classic IIFE) │ └─ phantom-cursor.js visual overlay of agent clicks ├─ background/ service worker │ ├─ index.js DeepSeek proxy · side-panel wiring · ATS proxy │ └─ runner.js background plan runner (state machine + watchdog) ├─ sidepanel/ the agent UI │ ├─ app.js agent loop · tool dispatch · chat UI │ ├─ prompt.js system prompt │ ├─ tool-defs.js ~30 native tool schemas (pure data) │ └─ deepseek.js SSE → direct → worker transport + retry ladder ├─ lib/ shared logic, Node-testable │ ├─ browser-tools · page-tools CDP + scripting executors │ ├─ state-store · output-writer dedup store · TSV/CSV │ ├─ extractor-* · plan · allowlist · redaction │ ├─ ats-adapters · site-verification · regex-guard │ └─ workspace · embedded-storage · locator ├─ shared/ constants · site configs └─ agent/ legacy JSON action parser test/ 677 offline unit tests

How the pieces talk

  • Content scripts serialize the page and render the phantom cursor; they never talk to the model directly.
  • Side panel owns the agent loop, the chat, and tool dispatch. It never touches the page realm for reading — it injects scripts instead.
  • Service worker proxies DeepSeek (the panel's CSP blocks cross-origin fetch), runs ATS fetches, and hosts the background plan runner.
  • lib/ is where security, storage, extractors and planning live — deliberately pure and unit-tested in plain Node.

The agent loop

Reliability built into every turn.

The loop, per step

  • Snapshot — the page is observed; a fingerprint decides whether a full PAGE REPORT or a short "unchanged" note is sent.
  • Context — the system prompt, the checklist, and the run event log are rebuilt and injected every turn.
  • Call — one DeepSeek call with native tool schemas; effort is routed by difficulty (low for routine steps, high for recovery).
  • Execute — tool calls run against the pinned tab; reasoning reasoning_content is preserved verbatim for the next call.
  • Collect — rows go through the dedup store; the model never holds data in memory.

Escalation ladder

  • Stuck page — an unchanged tree is counted; after repeated no-effect turns the agent escalates (refresh, go_back, or run_javascript on the target).
  • Unreadable page — Chrome error interstitials and blocked loads are named, not guessed; repeated failures trigger a "search-first" rule.
  • Search-first navigation — if direct-URL loads fail 3×, the agent stops using URLs for that site and drives its search bar with plain words.
  • "Model said no" — a refusal in the first steps, before any tool ran, is nudged to actually try (capped so it cannot loop).
  • Context budget — 100k-char conversation budget: trim oldest messages, drop history only with a marker, keep tool-call/result pairs together.

Degradation ladder (API)

DeepSeek's contract: any tool-calling request must replay reasoning_content verbatim. BAT sends tools on every interactive request, so it never truncates a thinking block — and if the provider rejects a parameter, it walks an ordered ladder instead of spinning:

enabled + effort→ enabled→ disabled→ omit

Transports cascade too: SSE stream → plain fetch → service-worker proxy, sharing one overall deadline so retries can never stack into a multi-minute stall. Retries use exponential backoff; 401/402/429 are reported in words the user can act on.

Data & files

The store is the authority; the file is a projection.

Collected rows land in an IndexedDB dedup store before any write — an append-only text file cannot merge duplicates, so dedup happens at the source.

Dedup store (state-store)

  • Rows keyed [collection, dedupKey]; keys normalize case, punctuation and whitespace — but preserve tech names (C++, C#, .NET, Node.js).
  • First row wins; a duplicate's source value is merged into the survivor's sources cell.
  • Counters give O(1) unique-row counts after every page write — no full re-reads mid-run.
  • Writes serialize per collection; NOT-FOUND bookkeeping is one atomic transaction.

TSV/CSV writer (output-writer)

  • Header written exactly once; appends go at end-of-file; cells are sanitized so one bad value can't break alignment.
  • CSV quoting is parsed with the same rules used to write it — "Company, Inc" never misaligns.
  • The file's state is cached and invalidated on size change (external edits, other writers).
  • The file itself is the authority for the running row count — never a number the model holds.

One fixed workspace

Files live in exactly one place, decided once and never silently moved:

  • Embedded storage — IndexedDB-backed, zero setup, never expires. This is the default until you pin a folder.
  • A pinned folder — via the File System Access picker; writes go to its data/ subfolder. If Chrome drops the grant on restart, Settings offers Reconnect folder — rows are safe in the store either way.

Background plan runner

Set it running; close the panel.

A service-worker state machine executes collection plans with zero model calls per page — the model is consulted only to synthesize an extractor when a site has none.

draft→ running→ done · awaiting_humancaptcha/login — never auto-solved · paused· failed

Resilience

  • Checkpoint after every page — position and counts persist to IndexedDB; eviction or restart never loses more than the page in flight.
  • Watchdog — a 30s chrome.alarms revives the loop if the worker is killed mid-run; onStartup recovers after a browser restart.
  • Page budgets — 25s for a normal page, 150s for extractor synthesis (a model call); a page that overruns is skipped and logged, never raced into the next page.
  • Politeness — randomized page delay plus a per-host floor so a wide sweep can't burst one site.

Extractor lifecycle

  • Synthesize — when a URL pattern has no cached extractor, the runner reads the page (redacted), asks the model for a pure DOM reader, and safety-screens it.
  • Validate — every replay is checked: schema fingerprint, required fields, row-count collapse against a trailing average.
  • Retire / halt — a failing extractor is retired (history kept); two consecutive failures halt the site; three failed pages abandon the unit — the run itself stays alive.
  • Human walls — CAPTCHA or login walls pause the run as awaiting_human; you clear it, then resume from that exact page.

ATS adapters

ats_fetch pulls entire company boards from Greenhouse, Lever, Ashby and Workable public JSON APIs in one HTTP call. Slug discovery tries likely variants and verifies identity, not just existence: a board that exposes its name must match, an unnamed board is accepted only if non-empty and flagged unverified. All rows normalize to {Title, Company, Location, Posted, URL} and flow through the same dedup store as scraped rows — cross-source dedup is automatic.

Security model

Model-authored code, treated as untrusted.

Every path where model output becomes a running action is gated. The allowlist is the real boundary; the screens make attacks expensive and visible.

Two-layer extractor screen sandbox

Extractors and run_javascript are model-written from attacker-controlled page markup, and the CDP path bypasses page CSP on purpose — so the screen is applied twice.

  • Regex denylist — ~30 rules: no network, no eval/Function, no storage, no timers, no postMessage, no DOM insertion, no navigation.
  • AST alias tracking (acorn) — closes what regex can't see: var w = window; w.fetch(), destructuring, IIFE parameters, Reflect.get, descriptor retrieval, enumeration of a tracked global.

Sensitive-value redaction privacy

Anything the agent reads can reach the model, so sensitive values never leave the page.

  • Fields caught by type, autocomplete token (cc-number, one-time-code…), and name/id (cvv, otp, secret…).
  • Raw markup sent to extractor synthesis is redacted too — inputs, textarea bodies, and unterminated tags can't smuggle a value through.
  • type=file local paths never surface.

Site allowlist control

Page-changing tools (and extractor code) are gated by an approved-sites list that fails closed when empty. Allow-all is an explicit opt-in for fresh installs.

  • Scheme is checked before allow-all — chrome://, file:// and data: are never "all sites".
  • Redirects off-list stop the run at the first page; the runner re-checks the origin it actually landed on.

Guarded regexes hardening

Every model-authored pattern is analyzed with safe-regex before compile.

  • A nested-quantifier pattern can hang V8's regex engine, so a catastrophic-backtracking shape is refused with a clear message.
  • Length-capped and fail-closed: a broken safety analysis rejects, it never silently passes.

Develop

Built with Vite, tested offline.

$ npm run dev          # vite dev server
$ npm run build        # production build → dist/
$ npm test             # 677 offline unit tests
$ npm run test:live    # + live ATS checks (needs network)
$ npm run lint         # eslint
$ npm run check        # lint + test + build

Testing strategy

  • The suite splits offline vs live: CI runs the deterministic offline tests only, so logic regressions can't merge green.
  • Security-critical modules (extractor-screen, redaction, allowlist, regex-guard) are asserted as pure functions.
  • The plan runner's state machine (decideUnitProgress, reconcileCheckpoint) is tested as pure logic — no browser needed.
  • CDP extractor expression correctness is proven by evaluating it under Node with a stubbed DOM.
