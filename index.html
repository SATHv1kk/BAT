BAT

A Browser Automation Tool that lives in your side panel. It reads any page through an accessibility tree, reasons over it, and drives the browser with native tool calls — click, type, navigate, extract, collect.

What it does

An agent that reads pages, not pixels.

BAT serializes a page into a clean, structured report the model can act on reliably, then executes every action with real browser tools.

🌳

Reads pages for the model

An accessibility tree + page text + checkbox state + JSON-LD product data, emitted as a fenced PAGE REPORT — so the model always acts on structure, never guesses.

🖱️

Native browser tools

left_click, type, form_input, navigate, scroll, run_javascript, get_links, find — executed via CDP and the scripting API, with a phantom cursor so you see every click.

📁

Collects data to files

A dedup store feeds TSV/CSV in a workspace folder (on disk or embedded), and give_file hands the finished file straight into the chat with a Download button.

⚙️

Background collection runs

A service-worker runner walks a plan page-by-page with cached extractors, checkpoints after every page, and survives panel close and browser restart.

✅

Keeps itself on track

A working checklist the model maintains (set_checklist) plus a per-run event log — both injected into its context every single turn.

🧲

Whole job boards via ATS

Greenhouse, Lever, Ashby and Workable public JSON APIs — an entire company board in one HTTP call, no tab and no extractor needed, merged into the same dedup pipeline.

How it works

Observe → decide → act → collect.

One loop, running against the real page in your browser.

01

Observe

Injects a serializer into every frame and builds the PAGE REPORT — accessibility tree with [ref_N] handles, visible text, checkboxes, product data. Sensitive values are redacted before anything leaves the page.

Decide

One DeepSeek call per step. The model picks a tool call against a live ref — click, type, set a checkbox, navigate — with its checklist and run log injected so it never works from memory.

03

Act

Tools run via CDP + the scripting API with page-idle waits, a phantom cursor, and stuck detection that escalates (search-first navigation, refresh, re-read) instead of looping.

form_input

Collect

Rows pass through a dedup store — first row wins, duplicate sources merge — then novel rows append to TSV/CSV in your workspace. give_file puts the finished file in the chat.

Security model

Model-authored code, treated as untrusted.

Every path where model output becomes a running action is gated.

Two-layer extractor screen sandbox

Model-written extractors and run_javascript pass a regex denylist and an AST alias-tracking pass (acorn) before running in the page realm — closing window.fetch aliasing, DOM-injection exfiltration and prototype-chain escapes.

Sensitive-value redaction privacy

Password, OTP, card and pin fields are caught by type, autocomplete token, name and id — and redacted before upload. type=file local paths never surface.

Site allowlist control

Page-changing tools are gated by an approved-sites list that fails closed when empty. Allow-all is an explicit opt-in for fresh installs; a redirect off-list stops the run.

Guarded regexes hardening

Every model-authored pattern is analyzed with safe-regex before compile, so a single catastrophic-backtracking pattern can never hang the extension.

Install

Running in about a minute.

No account, no server. Just a Chrome extension and your own DeepSeek key.

1

Build it

Clone the repo, install, and produce the dist/ bundle.

$ git clone https://github.com/SATHv1kk/BAT.git
$ cd BAT
$ npm install
$ npm run build
2

Load it

Load the unpacked extension from the built folder.

# chrome://extensions
Developer mode → Load unpacked
→ select dist/
3

Connect it

Open the side panel and add your DeepSeek key. Optionally pin a workspace folder for files on disk.

Ctrl + Shift + E open panel
